# Open-source globe-rendering repositories

Status: research recommendation, not an approved stack or implementation plan. Repositories and releases were checked 2026-09-07. “Inspected” means source was read at the named commit; it does not mean the package built or met a performance target.

## Recommendation

For a Three.js prototype, combine two narrow libraries behind an EarthHistory-owned scene and data contract:

1. **Adopt experimentally** `@takram/three-atmosphere` for the sky, solar lighting and aerial perspective.
2. **Adopt experimentally** `3d-tiles-renderer` for screen-space-error traversal, request scheduling, cache eviction, quantized-mesh terrain and imagery overlays.
3. Keep geological age, reconstruction scenarios, layer provenance, missing-data masks and time-slice transitions outside both libraries. Neither understands plate models or evidence uncertainty.

Do not assume this pair already produces the final orbital image. Takram’s globe-scale volumetric clouds remain unfinished, its present cloud renderer has spherical seams and no WebGPU path, and neither repository supplies an ocean material. Ocean Fresnel/specular response, cloud coverage from space, cloud shadows at globe scale and temporal surface synthesis remain prototype work.

## What the two source inspections established

### Takram: reuse the model, replace its modern-Earth defaults

The WebGL [`AerialPerspectiveEffect`](https://github.com/takram-design-engineering/three-geospatial/blob/b012ad06d858fc035d88aacfd73f092f93c994e4/packages/atmosphere/src/AerialPerspectiveEffect.ts#L47-L80) accepts an ellipsoid, sun direction, precomputed scattering textures, ground/sky lighting and overlays. [`AtmosphereParameters`](https://github.com/takram-design-engineering/three-geospatial/blob/b012ad06d858fc035d88aacfd73f092f93c994e4/packages/atmosphere/src/AtmosphereParameters.ts#L91-L155) exposes solar irradiance, bottom/top radius, Rayleigh, Mie, absorption and ground albedo, but defaults to a modern Earth-like 6,360–6,420 km atmosphere with modern-looking ozone/aerosol coefficients. `AerialPerspectiveEffect` also defaults to WGS84.

The [WebGPU implementation](https://github.com/takram-design-engineering/three-geospatial/blob/b012ad06d858fc035d88aacfd73f092f93c994e4/packages/atmosphere/WEBGPU.md#L5-L9) uses Bruneton-style 4D scattering LUTs, Hillaire-style multiple scattering and ray-marched aerial perspective. It requires Three >=0.182 and provides physically based large-scale lighting, but uses a new TSL/node API. Treat WebGPU and WebGL paths as separate prototype targets.

The cloud package supports weather textures, Beer shadow maps, temporal filtering and quality presets. Its own [limitations](https://github.com/takram-design-engineering/three-geospatial/blob/b012ad06d858fc035d88aacfd73f092f93c994e4/packages/clouds/README.md#L180-L210) say local weather is not tiled globally, cube-sphere seams remain, global coverage/space views are planned, and WebGPU is unsupported. These are acceptance blockers for the final orbital cloud layer, not reasons to reimplement its ray marcher immediately.

For deep time, do not call the bundled modern astronomy date functions with geological ages. EarthHistory should supply a normalized illustrative sun direction and separately label it from geological age. Atmosphere parameter sets should be cited scenarios, not silently animated between modern defaults.

### NASA-AMMOS: reuse scheduling and format adapters

[`TilesRendererBase`](https://github.com/NASA-AMMOS/3DTilesRendererJS/blob/d83f3714004cb2e880cce3d755be6b7e974fd031/src/core/renderer/tiles/TilesRendererBase.js#L371-L405) separates traversal from the rendering engine. Its update loop combines screen-space error, prioritized downloads, parse/process queues and an [LRU cache lifecycle](https://github.com/NASA-AMMOS/3DTilesRendererJS/blob/d83f3714004cb2e880cce3d755be6b7e974fd031/src/core/renderer/tiles/TilesRendererBase.js#L474-L494). Plugins can replace fetching, parsing, visibility, error calculation and attribution rather than requiring a fork.

The [`QuantizedMeshPlugin`](https://github.com/NASA-AMMOS/3DTilesRendererJS/blob/d83f3714004cb2e880cce3d755be6b7e974fd031/src/three/plugins/QuantizedMeshPlugin.js#L139-L189) converts a quantized-mesh `layer.json` hierarchy into 3D Tiles traversal and builds terrain against the renderer ellipsoid. [`ImageOverlayPlugin`](https://github.com/NASA-AMMOS/3DTilesRendererJS/blob/d83f3714004cb2e880cce3d755be6b7e974fd031/src/three/plugins/images/ImageOverlayPlugin.js#L58-L67) composites XYZ, TMS, WMTS, WMS and GeoJSON sources per terrain tile. That is the strongest evidence that ancient elevation and visual derivatives can use established paging/cache mechanics. A small custom time-slice source/plugin can switch versioned offline assets and abort stale requests while EarthHistory retains source IDs and epistemic status.

The library does not prescribe an Earth-only globe: its ellipsoid is triaxial and its examples include Moon and Mars. WGS84/provider assumptions enter through chosen plugins and datasets. WebGPU remains a risk because overlay/material wrappers use Three shader customization and the repository documents WebGL renderer types; prove the required plugin set on both backends.

## Evidence and next decision

Open Source MCP built code graphs for the two recommended repositories, then source modules and package licences were inspected at the SHAs above. No dependency install, build, automated test or performance measurement was run. A coordinating browser smoke check rendered Takram’s basic atmosphere and NASA’s Mars terrain; Takram’s Google/Manhattan example required an API key, and the initial Mars view showed LOD gaps. This confirms runnable demos only, not globe-scale visual quality or performance.

The next stack decision should follow one bounded comparison scene: the same offline modern control slice in (A) Three + Takram + 3DTilesRendererJS and (B) CesiumJS. Stop the comparison when one option fails any required capability: orbital and regional camera range, physically credible terminator/limb, ocean glint, global cloud coverage and shadows, crisp overlays, time-slice cancellation, WebGL fallback, or the agreed frame-time/memory budget. Keep generated terrain and ancient surface inputs identical so the test measures render/streaming architecture rather than data quality.
