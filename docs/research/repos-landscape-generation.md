# Reusable landscape and terrain-generation repositories

Research snapshot: 2026-09-07. This is a source review for stack discussion, not an approved architecture or a validation of model results. No package was installed and no model was executed. GitHub metadata, current documentation, license files, and targeted source at the named commits were inspected. goSPL, Badlands, and World Orogen received graph-first inspection with the Open Source MCP repository manager, graph overview, Cypher queries, and targeted source reads; the other candidates received bounded repository-metadata and documentation review. “Scientifically modelled” below means that the code implements published/process-based equations; it does not mean that an unconstrained run reconstructs the real past.

## Recommendation

Do not build spherical meshing, terrain enrichment, erosion-shaped drainage, or worker plumbing from scratch. With minimal source data and most processing required in the frontend, the baseline changes from a two-scale scientific solver pipeline to a browser-native synthesis pipeline:

1. Use **World Orogen** as the closest architectural reference for spherical browser generation: feed a constrained palaeo-height/land mask into a Web Worker, add bounded deterministic detail and drainage, and send typed arrays to Three.js. Direct reuse requires accepting GPL-3.0; otherwise independently implement similar small interfaces from permissive or published sources.
2. Keep **goSPL** as an optional offline research/validation path for chosen global slices, not the baseline runtime. Its MPI/PETSc stack conflicts with frontend-first processing.
3. Use **Badlands** only for evidence-rich regional basins and margins where source-to-sink stratigraphy justifies a prepared asset.
4. Use **Landlab** for permissively licensed offline experiments and **HighMap** as an algorithm/visual reference.

The browser can generate visual fields from small reconstructed inputs, while regional scientific models remain optional prepared assets. None of these repositories is a complete orbital globe application with provenance, uncertainty, plate-model compatibility, streaming, and realistic atmosphere/ocean rendering.

## Frontend-first follow-up: World Orogen seams

The most reusable boundary is not the whole application. [`sphere-mesh.js`](https://github.com/raguilar011095/planet_heightmap_generation/blob/cc2662b4edd52231c4f65d8765f3ef12cd82d9b7/js/sphere-mesh.js#L1-L219) cleanly builds a typed-array Fibonacci sphere, stereographically triangulates it with Delaunator, closes the pole, and exposes flat adjacency arrays. [`generate.js`](https://github.com/raguilar011095/planet_heightmap_generation/blob/cc2662b4edd52231c4f65d8765f3ef12cd82d9b7/js/generate.js#L1-L58) dispatches generation to one module Web Worker, and its heightmap entry transfers the grayscale buffer rather than copying it ([source](https://github.com/raguilar011095/planet_heightmap_generation/blob/cc2662b4edd52231c4f65d8765f3ef12cd82d9b7/js/generate.js#L895-L992)). The worker retains cloned mesh/elevation state for cheap reapplication and returns transferable typed arrays ([source](https://github.com/raguilar011095/planet_heightmap_generation/blob/cc2662b4edd52231c4f65d8765f3ef12cd82d9b7/js/planet-worker.js#L824-L1097)). These interfaces map well to `constrained fields -> deterministic synthesis worker -> render buffers`.

The existing importer converts an image to 8-bit luminance in a canvas ([source](https://github.com/raguilar011095/planet_heightmap_generation/blob/cc2662b4edd52231c4f65d8765f3ef12cd82d9b7/js/import-main.js#L29-L57)); the worker bilinearly samples that equirectangular array on spherical cells, with longitude wrapping. EarthHistory should replace the 8-bit elevation convention with typed numeric elevation, land/sea, validity, and constraint masks plus explicit units and provenance. The sampling and adjacency machinery can remain.

All terrain synthesis is CPU JavaScript in the worker. [`terrain-post.js`](https://github.com/raguilar011095/planet_heightmap_generation/blob/cc2662b4edd52231c4f65d8765f3ef12cd82d9b7/js/terrain-post.js#L399-L756) repeatedly sorts and sweeps land cells for glacial, hydraulic, and thermal passes; its priority flood also traces drainage paths and sorts cells ([source](https://github.com/raguilar011095/planet_heightmap_generation/blob/cc2662b4edd52231c4f65d8765f3ef12cd82d9b7/js/terrain-post.js#L78-L234)). Those are plausible scaling bottlenecks from code structure, not measured findings. The app records and prints worker, transfer, mesh-build, and per-stage timings ([source](https://github.com/raguilar011095/planet_heightmap_generation/blob/cc2662b4edd52231c4f65d8765f3ef12cd82d9b7/js/generate.js#L313-L370)), but the repository supplies no controlled benchmark baseline. Start below its high-detail settings and measure target devices before considering WebGPU compute.

The GPU renders geometry; it does not generate terrain. The globe uses Three.js/WebGL, a simple atmosphere shader, Phong water, and Lambert vertex-coloured land ([source](https://github.com/raguilar011095/planet_heightmap_generation/blob/cc2662b4edd52231c4f65d8765f3ef12cd82d9b7/js/scene.js#L1-L100)). These are useful scaffolding, not the realistic atmosphere/ocean target. Seeded PRNG and packed planet codes reproduce one static parameterised world ([source](https://github.com/raguilar011095/planet_heightmap_generation/blob/cc2662b4edd52231c4f65d8765f3ef12cd82d9b7/js/planet-code.js#L197-L244)); there is no temporal evolution model. For a time slider, generate stable detail once in plate-local coordinates and advect it, or cache keyed slices. Regenerating every age independently would visibly flicker and would not create geological history.

## What the targeted source review established

goSPL is more than a project description. At commit `9a1ca279…`, its tectonic update reads per-interval NPZ horizontal displacement, vertical displacement, and optional target palaeoelevation, then advects the mesh ([source](https://github.com/Geodels/gospl/blob/9a1ca279b311148db87e8ed9c9b68f24f40a98ef/gospl/mesher/tectonics.py#L60-L150)). Rainfall maps are treated as runoff unless evaporation/infiltration is prepared or configured separately ([source](https://github.com/Geodels/gospl/blob/9a1ca279b311148db87e8ed9c9b68f24f40a98ef/gospl/mesher/unstructuredmesh.py#L924-L988)). Deposited material updates persistent thickness, porosity, coarse/fine fractions, erodibility and optional provenance ([source](https://github.com/Geodels/gospl/blob/9a1ca279b311148db87e8ed9c9b68f24f40a98ef/gospl/sed/stratplex.py#L639-L718)). Its regular-grid exporter derives shoreline-aware D8 hydrology per output step, useful for browser assets ([source](https://github.com/Geodels/gospl/blob/9a1ca279b311148db87e8ed9c9b68f24f40a98ef/gospl/analyse/gridexport.py#L573-L623)).

Badlands likewise contains the needed regional mechanics. At `975f595…`, sediment routing separates erosion from alluvial-plain, closed-basin, and marine deposition and tracks multiple rock fractions ([source](https://github.com/badlands-model/badlands/blob/975f595ae313dd08d674c0effde18b5e8155f997/src/badlands/flow/flowNetwork.py#L687-L1013)). It interpolates time-selected rain maps onto the TIN ([source](https://github.com/badlands-model/badlands/blob/975f595ae313dd08d674c0effde18b5e8155f997/src/badlands/forcing/forceSim.py#L357-L415)) and accepts regular-grid vertical or 3-D displacement histories ([source](https://github.com/badlands-model/badlands/blob/975f595ae313dd08d674c0effde18b5e8155f997/src/badlands/forcing/forceSim.py#L515-L658)). Its stratigraphic wedge preserves palaeodepth and thickness by rock type in HDF5 ([source](https://github.com/badlands-model/badlands/blob/975f595ae313dd08d674c0effde18b5e8155f997/src/badlands/underland/stratiWedge.py#L25-L220)).

## Bounded evaluation before adoption

Use one constrained test shared by the candidates: a small synthetic rift-basin-to-shelf domain with prescribed uplift/subsidence, rainfall, sea-level change and two sediment classes. Compare mass balance, drainage stability, depocentre migration, preserved stratigraphy, deterministic reruns, wall time, memory, and export effort. Trace source and forcing IDs through a versioned external manifest and wrapper when the solver does not store arbitrary provenance fields itself. Stop evaluating a solver if traceability cannot be maintained with a bounded adapter, the test cannot be reproduced deterministically, or browser-ready fields require an unbounded custom fork. Separately test visual enrichment by downsampling a modern DEM, withholding the fine DEM, and measuring whether generated normals/detail improve appearance without moving constrained coastlines, drainage trunks, or basin geometry.
